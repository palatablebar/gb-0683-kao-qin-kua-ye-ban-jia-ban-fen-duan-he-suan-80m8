# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 社保缴费基数申报（M8）

工资期间取班次归属日所在月（`shift_day[:7]`）；无归属日时取实际日历日。期间也可由 `parameters.declare_period`（YYYY-MM）显式指定，非法值返回 `PERIOD`。

裁决：在途工资（缺少时薪、同版冲突、缺卡、列数不齐等隔离项）**不计入本次申报基数**，逐项登记为 `后续补报候补`；工资复核确认后，下一批次按 `后续补报` 计入新增基数。这样既不因等待跨月加班而延后当期权益，也不漏报随后补入的加班。已确认工资按计算证据逐项映射。

逐项对应：每个已确认计算证据与每条隔离证据各成一申报项，字段含工资期间、班次归属日、日历日、分类或原因、分钟、金额、处理方式、规则版本、申报批次。处理方式只有四种：

- `计入本次申报基数`：本期已确认且先前未申报；
- `已申报（不重复计入）`：本期在相同规则签名下已申报过，重跑不再计入；
- `后续补报候补`：待核项目（金额为 `null`，不作为零）；
- `非本期`：工资期间与申报期间不同。

申报期间、已确认项、待核项、申报基数、后续补报合计逐项对应；`totals.mapping_items` 必须等于 `calculations + quarantine` 条数，否则阻断。

规则签名 = 规则版本 + 计算参数（法定假日列表等）。规则签名变化时，先前申报在提交新申报的同一事务中置为 `作废`，新申报以 `待复核` 入账，须重新核对；作废记录不可复核（`VOID` 409）也不可导出。

幂等：`filing_id` 由期间、输入批次身份（输入字节+参数+规则版本）与规则签名派生；同一批次重新运行得到同一 `filing_id`，再次提交返回 `unchanged`，不新增申报记录。`退回` 的申报重新提交时复用同一条记录并回到 `待复核`。

闸门：对账未平（输入≠采纳+隔离+空行+重复表头+完全重复）或映射未覆盖全部证据时 `declarable=false`，申报返回 `DECLARE_BLOCKED`（409），导出返回 `UNBALANCED`（409）。导出自检要求列数对齐、申报项行数等于映射行数、申报项合计等于申报基数、申报未作废。

页面与导出一致：屏幕展示的逐项行与导出 CSV 来自同一份申报结果；未提交时屏幕标 `待提交` 且不提供导出链接；已提交时导出链接指向与屏幕同一 `filing_id` 的记录。

恢复与留存：批次写入是单事务（旧 body 先追加到 `run_revisions` 再更新当前 body 与 latest 指针），生成中断不产生半写批次；`source_b64` 与 `run_revisions` 保留原始工资与打卡，`GET /api/runs/<id>/source.csv` 可取回；`/api/runs/<id>/revisions` 列出历史，`.../restore` 提升旧版，记录只增不删。
